# Engine identifier table

Engine identifiers that the Python scripts, the plugin tests and the build files hardcode, and that an engine upgrade could rename, move or remove. It is the checklist for a 5.8 to 5.9 upgrade: each row names the identifier, what kind of name it is, where it is used, and what fails if it changes.

## Scope and method

- Searched: `Scripts/*.py` (not `Scripts/archive/`), `Plugins/MotionTerminal/Source/`, `Plugins/MotionTerminal/Tests/`, `Source/`, `MotionTerminal.uproject`, `Plugins/MotionTerminal/MotionTerminal.uplugin`, and the `*.Build.cs` and `*.Target.cs` files. Not searched: `private/`, `Config/`.
- Locations are `file:line`. A row gives the number of distinct lines and the first three (all when there are three or fewer). A mention after `#` in Python or `//` in C++ is marked `(comment)`; a docstring or block-comment mention counts as code, so a count can overstate real uses.
- Sections 1 to 3 were checked against declarations in the headers under `<UE_5.8>/Engine/Source` and `<UE_5.8>/Engine/Plugins`; every name was found. That shows the name is valid on 5.8, not that it survives to 5.9, which is to confirm on 5.9.
- "What breaks" is the failure given how the name is used at that location, read from the calling code; where the calling code does not check a result, the row says so.
- Not enumerated: methods and properties on `unreal.*` objects, property paths passed to node-property setters (for example `CurveBlendOption`).
- Rig pin paths are not enumerated either; they are checked where they are written instead. 5.9 renamed `FRigDynamicsSimulationDragSettings.LinearDragMultiplier` to `LinearDampingMultiplier` (`<UE_5.9>/.../ControlRigDynamics/Public/RigDynamicsData.h:255`). The engine's property redirect covers binary loads only, so the rig's text pin default fell back to the engine default of 1, which re-enabled the native linear drag. Every pin default and node add in `dynamics_rig.py` and `leg_reach.py` now raises when the controller refuses it, and `report()` lists `pins_missing`.

## Highest-risk names for 5.9

Selected from evidence in the 5.8 install only; nothing here comes from 5.9.

- `RigUnit_SpawnDynamicsSolver1`: the unsuffixed struct is already `Deprecated = "5.8"` and the live one carries a `1` suffix (`RigDynamicsSolverExecution.h:24`, `:67`). Used at `Scripts/dynamics_rig.py:49`.
- `RigVMFunction_MathVectorSelectBool`: `Deprecated = "4.26.0"` in 5.8 and still used by the reach rig (`Scripts/leg_reach.py:96`).
- Names owned by the Experimental plugins `ControlRigDynamics`, `ModelContextProtocol`, `ToolsetRegistry`, `EditorToolset` and `Terminal` (`IsExperimentalVersion` in their `.uplugin` files): module, struct, class and setting names there are the likeliest to move.
- `-ReportExportPath`: renamed from `-ReportOutputPath` in 5.8 (`Scripts/run_verification.py:10`), so command-line flags do change between releases.
- The debug-line substrings matched by the PIE tests and drive scripts (section 2): they depend on engine text formats rather than on declared names, so a header diff does not show them.
- The editor's node-instance counter in the dynamics baselines (`AnimGraphNode_X_<n>`).
